# UI Wireframe

狀態：`Proposal`

這是 SnipPlus 的低保真 UI 草稿，只用來討論可能的使用者流程與畫面責任。它不是已核准需求，也不代表截圖功能已開始實作。產品範圍、平台與互動細節仍須由 PRD 與 Spec 核准。

## Wireframe 原則

- 主要任務應能從單一入口開始。
- 進行中的操作要清楚顯示狀態、取消方式與結果去向。
- 不把工具列、設定與結果處理混成同一個畫面責任。
- 失敗狀態必須提供可理解的原因與下一步。

## Candidate flow

```text
+----------------------+       +----------------------+       +----------------------+
| 1. Ready              |       | 2. Selecting         |       | 3. Result             |
|----------------------|       |----------------------|       |----------------------|
| [SnipPlus]           |       | [Cancel]             |       | [New] [Save] [Copy]  |
|                      |       |                      |       |                      |
| [Start]              | ----> | Select an area       | ----> | Preview / result      |
| [Settings]           |       | [Esc: cancel]        |       | [Edit? TBD]           |
|                      |       |                      |       |                      |
| Recent: TBD          |       | Status: active       |       | Status: ready         |
+----------------------+       +----------------------+       +----------------------+
          ^                              |                              |
          |                              v                              |
          +------------------------ Cancel / Error ----------------------+
```

## State responsibilities

| State | User goal | Required decision |
| --- | --- | --- |
| Ready | 開始主要任務或調整設定 | 啟動方式、快捷鍵、最近項目是否需要 |
| Selecting | 指定操作範圍並可取消 | 支援的選取方式、取消鍵、焦點與多螢幕行為 |
| Result | 查看、交付或保存結果 | 結果格式、保存位置、剪貼簿與隱私策略 |
| Error | 知道失敗原因並恢復 | 錯誤分類、重試、取消與診斷資訊 |

## 尚未核准的問題

- 產品是否確定是 desktop app？
- 支援哪些作業系統、顯示器與縮放比例？
- 是否需要全螢幕、視窗、區域或延遲等模式？
- 結果是否保留在本機？保存多久？
- 是否需要編輯、註記、OCR、分享或雲端功能？
- `Save`、`Copy` 與快捷鍵的成功與失敗回饋為何？

上述問題在 PRD 與 Specs 核准前保持 `TBD`，不直接轉成程式碼或 acceptance criteria。
